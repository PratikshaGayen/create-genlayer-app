## Quickstart

```sh
# 1. Install JS deps
npm install

# 2. Install Python deps (use a venv)
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt

# 3. Lint the contract (no Docker needed)
genvm-lint check contracts/storage.py

# 4. Run direct-mode tests
pytest tests/direct/ -v
```

## Deploying to a network

```sh
genlayer network set localnet
genlayer deploy --contract contracts/storage.py
```

Then set the deployed address in `app/.env` under
`VITE_CONTRACT_ADDRESS` and `npm run dev:app`.

## Why a pinned runner hash?

The `test` and `latest` runner aliases (and any unversioned runner
reference) are local-only. All GenLayer networks reject them. The hash
in `contracts/storage.py:1` is the current published runner from the
official `genlayer-dev` skill
(https://github.com/genlayerlabs/skills/blob/main/plugins/genlayer-dev/skills/write-contract/SKILL.md).
The two independent sources that confirm it (the skill source and the
`genvm-runners-all.tar.xz` artifact on the corresponding `genlayerlabs/genvm`
release) are cited in the contract's own docstring.
